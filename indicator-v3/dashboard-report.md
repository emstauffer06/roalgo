# v3 dashboard implementation evidence

Local implementation verified 2026-10-05. The dashboard uses RoAlgoMarketDashboard and retains mount, setStatus, render, append, clear, setProgress, setSelection, setCollapsed, inspect, testActivate and destroy.

The six comparison selectors are coupled, independent, numeric, raw, memory and zero. Zero is explicitly an unfitted zero-forecast cash baseline. Fold navigation uses selectFold(index); configuration buttons use selectConfiguration(id) for grouped24/grouped48. Loaded study configurations control which buttons are active; unavailable configurations cannot invoke their callbacks. The active fold, configuration, variant, policy, node and recorded node count are inspectable GUI attributes. inspect() additionally returns the presentation description used to bind the active state. The default session profile is 80 / 20 / 20.

The 1260 x 1000 dashboard includes rolling-study navigation, selected-fold metrics and chart, six-comparison table, native/numerical node inspection, recorded market drives, a trade ledger, independent fold summaries and forecast contributions. The terminal scales to the available viewport and retains a compact mode. Forty-eight possible node buttons are shown only when the recorded state has those nodes. Switching from 48 to 24 nodes clamps the active node to available data. Raw, memory and zero comparisons identify native state as a diagnostic unused by the selected comparison.

Saved configuration saved_v2_24 displays SAVED V2 / READOUT REFIT, original 24 nodes per rig, eight drives, state dimension 51 and raw dimension 33. It uses the original v2 drive meanings and hides the four extra v3 drive rows. This view does not relabel saved v2 physics as the newer mechanical architecture. Normal v3 snapshots retain twelve-drive inspection and 24/48 node support.

Every comparison row includes validation mean-return MSE and its ratio to the zero forecast, taken directly from report.validationMeanMSE and report.validationMseRatioToZero. Missing metrics remain blank. The selected model's input-stability panel displays retained/original dimensions, dropped-feature count, the clipping threshold and clipped-row counts for validation and evaluation. Validation counts come from preprocessing.validationClipping; evaluation counts come from actual result.rows prediction.clipping metadata. Zero is labeled as requiring no fit, normalization or clipping.

Selected policy identity comes from comparison.report.selectedPolicyId, accompanied by policySelectionReason, including no_candidate_passed_validation_gates and model_unavailable. The displayed search budget comes from recorded policyCandidates and flags inconsistent nonzero budgets. The budget applies to fitted models; zero explicitly has no policy search. Comparison text uses shared evaluation bars and cost assumptions without claiming every model selected the same policy.

Aggregate rows are filtered by the selected configuration and display the supplied arithmetic meanNetReturn, worstDrawdown, totalTrades and valid/attempted fold counts per model. They never compound returns, invent continuity, or choose an evaluation winner. Missing aggregate data clears old rows. The independent-fold equity convention is visible in both navigation and the aggregate title.

The pure Dashboard.describe(snapshot, selection) function is used by render and inspect. It was added after an observed failing data-binding test. The saved-refit changes also began with an observed failing test for the missing saved-v2/eight-drive identity before implementation. Tests exercise actual production logic without constructing simulated Roblox objects or claiming native layout success.
